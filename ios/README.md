# MControl for iOS

iPhone版のMControlです。Android版とは送信方式が異なります。

全体・伸縮・振動の3つを、それぞれパターン1〜9と停止で操作できます。
伸縮と振動は、別々のパターンで同時に動かせます。

## 送信方式

iPhoneのアプリは、BLEの広播でManufacturer Data（製造者データ）を自由に設定できません。
そのため、16bitのService UUIDを並べて命令を送っています。

機器が読んでいるのは、先頭の6個（12バイト）だけです。
位置がずれると動きません。7個目以降は、動作には使われていません。

| 位置 | 内容 |
|---|---|
| 1〜4 | 08F9 / 2349 / CBAE / D1C1（固定の前置き） |
| 5〜6 | 命令（下の表） |
| 7〜13 | 0D0C / 0F0E / 1110 / 1312 / 1514 / 1716 / 1918（公式アプリにそろえた詰め物） |

| 停止 | 9C6E / 0B3D | 1F5E / 0B0C | 982E / 0B7F |
| 1 | 156F / 0B2C | 965F / 0B1D | 112F / 0B6E |

| 3 | 076D / 0B0F | 845D / 0B3E | 032D / 0B4D |

全体は、公式のiPhoneアプリから観測した値です。
伸縮と振動は、Android版の命令から下の式で計算した値で、すべて実機で動作を確認しました。

## Android版の命令からの変換

Android版は、製造者データに「前置き8バイト＋命令3バイト」を入れて送ります。
iPhone版の先頭12バイトは、それを決まった値でXORしたものになっています。

```
前置き（8バイト）: Android版の前置き XOR 94 BE 0A ED 39 35 83 AD
命令（3バイト）  : Android版の命令   XOR 8B 89 40
12バイト目       : 0B（固定）
```

できた12バイトを、2バイトずつ下位・上位の順に読んで16bitのUUIDにします。

```
例：全体・パターン1
Android版の命令 : E4 9C 6C
XOR 8B 89 40    : 6F 15 2C
＋ 0B           : 6F 15 2C 0B → UUID 156F / 0B2C
```

この式は、手元の機器1台（前置き 6DB643CE97FE427C）で確認したものです。
前置きが違う他の機種で通用するかは、確認していません。

## 機器の動き

- 機器は、チャンネルごとに最後に受け取った命令を覚えて動き続けます
- iPhoneは電波を1種類しか同時に出せませんが、伸縮→振動と順番に送れば、両方を別々のパターンで動かせます

## ビルド時の設定

ソースコード以外に、Xcodeで次の設定が必要です。

- Minimum Deployments：iOS 17.0
- Build Settings：`INFOPLIST_KEY_NSBluetoothAlwaysUsageDescription`（Debug・Release両方に説明文を入れる）
- Build Settings（User-Defined）：`ASSETCATALOG_COMPILER_APPICON_NAME` = `AppIcon`
  （これがないとアイコンがアプリに入らず、仮のアイコンが表示されます）
- Signing & Capabilities：Background Modes → Acts as a Bluetooth LE accessory
  （追加しましたが、アプリを開いたままで動いたため、必要かは未確認です）

## 動作確認環境

- Xcode 27
- iPhone 13 mini（iOS 26.6.2）
- アプリが前面にある状態で確認

新しいBluetoothチップを積んだ機種では、Service UUIDの広告がうまく届かないという報告があります。
新しいiPhoneでの動作は確認していません。

## 注意

- 無料のApple IDで入れた場合、7日ごとにXcodeから入れ直す必要があります
- この機器には認証がありません。使わないときは電源を切ってください
